    Etapa 5 — SDK2: mover o robô por código ✔¶

    Validada em 30/07 — StandDown, StandUp e BalanceStand executados com ret: 0 e o robô obedecendo fisicamente.

    A arquitetura em uma linha

    seu script Python → SportClient → DDS: rt/api/sport/request → serviço "sport" no robô → controlador de locomoção → motores
                              ← DDS: rt/api/sport/response (ret: 0 = sucesso)
    Nada disso é ROS. O unitree_sdk2py fala DDS puro (CycloneDDS 0.10.2) com serviços embarcados no robô — os mesmos tópicos /api/... que vimos na lista do Jetson.

    1. Instalação (validada)¶

    No container casa:

    apt install -y python3-pip
cd /root/rima_ws
git clone https://github.com/unitreerobotics/unitree_sdk2_python
cd unitree_sdk2_python
pip3 install -e .

    ✅ Teste de aceite

    Successfully installed ... cyclonedds-0.10.2 ... unitree-sdk2py-1.0.1. Repare: o pip baixou o cyclonedds como wheel pronto do PyPI — não precisou compilar nada.

    Carta na manga (se o wheel não existir, ex.: outra arquitetura)

    Já temos o cyclonedds 0.10.x compilado da Etapa 4: export CYCLONEDDS_HOME=/root/rima_ws/unitree_ros2/cyclonedds_ws/install/cyclonedds e repita o pip3 install -e ..

    2. Os dois padrões de conversa do SDK¶

    Padrão A — pub/sub (ler o robô)¶

    O robô publica estado continuamente; você assina e recebe via callback. Script validado:

    import time, sys
from unitree_sdk2py.core.channel import ChannelSubscriber, ChannelFactoryInitialize
from unitree_sdk2py.idl.unitree_go.msg.dds_ import SportModeState_

def cb(msg: SportModeState_):
    print(f"body_height={msg.body_height:.3f}  mode={msg.mode}  yaw_speed={msg.yaw_speed:+.4f}")

if __name__ == "__main__":
    ChannelFactoryInitialize(0, sys.argv[1])   # domínio DDS 0 + SUA interface
    sub = ChannelSubscriber("rt/sportmodestate", SportModeState_)
    sub.Init(cb, 10)                           # callback + fila de 10 msgs
    time.sleep(5)                              # segura o processo vivo

    Linha a linha: ChannelFactoryInitialize(0, iface) cria o participante DDS amarrado à interface do robô (por isso passamos $IF_ROBO); ChannelSubscriber assina o tópico DDS cru rt/sportmodestate — que é o mesmo /sportmodestate do ROS, visto sem o "tradutor" (o prefixo rt/ é a convenção que o ROS 2 usa por baixo). Observação medida ao vivo: esse tópico publica a ~100 Hz (centenas de callbacks em 5 s), contra ~15 Hz do LiDAR — estado é barato, sensor pesado é caro.

    Padrão B — request/response (comandar o robô)¶

    Cada ação de alto nível é uma chamada RPC transportada por DDS. Quando você chama sc.StandUp(), o SportClient:

    1. Monta uma mensagem Request com um api_id (o número da ação) e os argumentos serializados como string JSON no campo parameter;
    2. Publica em rt/api/sport/request;
    3. Espera a resposta em rt/api/sport/response (até o SetTimeout);
    4. Devolve o código: ret: 0 = aceito/executado; ≠ 0 = erro (o que fazer).

    Os api_id das ações principais (confirme a lista completa no seu clone — comando abaixo):

    api_id Método O que faz
    1001 Damp() Amortece: motores relaxam (robô "desliga a força" com cuidado)
    1002 BalanceStand() Em pé com equilíbrio ativo
    1003 StopMove() Para qualquer movimento
    1004 StandUp() Levanta (postura rígida)
    1005 StandDown() Deita
    1006 RecoveryStand() Recuperação: levanta até de posições ruins
    1007 Euler(r,p,y) Inclina o corpo (roll/pitch/yaw) parado
    1008 Move(vx,vy,vyaw) Velocidade contínua — ver seção abaixo
    1009 / 1010 Sit() / RiseSit() Senta / levanta do senta 
    grep -n "API_ID" /root/rima_ws/unitree_sdk2_python/unitree_sdk2py/go2/sport/sport_api.py

    3. O script validado (posturas discretas — o degrau seguro)¶

    Desenhado para o pior caso de um Ctrl+C ser um robô parado (nunca um robô fugindo), com ENTER entre cada ação:

    import sys, time
from unitree_sdk2py.core.channel import ChannelFactoryInitialize
from unitree_sdk2py.go2.sport.sport_client import SportClient

if __name__ == "__main__":
    ChannelFactoryInitialize(0, sys.argv[1])
    sc = SportClient()
    sc.SetTimeout(10.0)   # quanto esperar pela response antes de erro
    sc.Init()
    input("Mao fora do robo. ENTER para DEITAR (StandDown)... ")
    print("StandDown ret:", sc.StandDown()); time.sleep(3)
    input("ENTER para LEVANTAR (StandUp)... ")
    print("StandUp   ret:", sc.StandUp()); time.sleep(3)
    input("ENTER para equilibrio ativo (BalanceStand)... ")
    print("Balance   ret:", sc.BalanceStand()); time.sleep(2)
    print("Fim. Robo em pe, postura estavel.")

    ✅ Teste de aceite — validado

    ret: 0 nas três ações e o robô obedecendo fisicamente (deitou → levantou → firmou).

    Checklist antes de QUALQUER script de movimento

    Robô em pé no chão (nunca em mesa), ~2×2 m livres, cabo ethernet com folga (ele abaixa e levanta!), controle ligado na mão, bateria ok, mãos fora do robô durante a execução.

    4. Próximo degrau: Move() — velocidade contínua, com respeito¶

    Move(vx, vy, vyaw) comanda velocidades (m/s e rad/s). Segurança embutida que você precisa entender: cada Move vale por um curto intervalo — se o seu programa morrer, o robô para sozinho (watchdog). Consequência: andar contínuo = reenviar o comando periodicamente (~10 Hz); parar = StopMove(). Exercício opcional (área maior: 3–4 m livres à frente; robô em BalanceStand antes):

    import sys, time
from unitree_sdk2py.core.channel import ChannelFactoryInitialize
from unitree_sdk2py.go2.sport.sport_client import SportClient

if __name__ == "__main__":
    ChannelFactoryInitialize(0, sys.argv[1])
    sc = SportClient(); sc.SetTimeout(10.0); sc.Init()
    input("3-4m livres a frente? Controle na mao? ENTER p/ andar 2s a 0.3 m/s... ")
    try:
        t0 = time.time()
        while time.time() - t0 < 2.0:
            sc.Move(0.3, 0.0, 0.0)   # vx=0.3 m/s, reto
            time.sleep(0.1)          # reenvio a ~10 Hz
    finally:
        sc.StopMove()                # SEMPRE, mesmo com Ctrl+C
        print("StopMove enviado.")

    O try/finally garante o StopMove() até se você interromper no meio — grave esse padrão.

    5. O mapa completo (até onde vai este nível)¶

    O que usamos é a API de alto nível: você pede intenções ("levanta", "anda a 0.3 m/s") e o controlador embarcado resolve as pernas. Existe o baixo nível (/lowcmd / /lowstate): comandar cada junta individualmente, torque a torque — é o terreno onde políticas de RL substituem o controlador de fábrica (exatamente o tema da palestra de quinta na summer school, "How Do You Teach a Robot to Walk?"). É poderoso e perigoso; fica mapeado como fronteira, não como exercício desta preparação.
